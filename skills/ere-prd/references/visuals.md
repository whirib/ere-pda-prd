# 按需配图与生成工具

改写自 PM-Skills `utility-mermaid-diagrams`。上游只负责 Mermaid 写法，本项目补上实际生成、版本与查看回执。

## 怎么决定

模型先识别沟通困难：读者是否需要追踪分支、责任交接、状态回退、关系或真实趋势。记录图的目的、读者、相关需求、类型和选择理由。若列表/表格更清楚就不画；没有固定“每 PRD 至少两张图”。

| 内容 | 默认形式 |
|---|---|
| 简单线性行动 | 编号列表 |
| 精确规则、数值、权限矩阵 | 简单表格 |
| 分支条件、回退/重试 | 流程图 |
| 多角色/多系统按时间交互 | 时序图/泳道图，接可用 renderer |
| 状态生命周期与可逆动作 | 状态图 |
| 真实时间趋势 | 折线图，时间轴按实际间距 |
| 类别数值比较 | 柱状图，标清单位和来源 |

不是自动关键词匹配。`visuals.decisions` 留下模型判断，代码校验需要的图确实生成且对应当前 PRD。内置流程图还会拒绝只有线性步骤的“图”。

## 实际生成

`render` 事件调用 Node 内置绘图工具，输出 SVG 和可编辑 Mermaid/JSON。它不依赖网络、Mermaid CLI 或图像生成账户。流程/状态图支持 2–16 节点及可选坐标；超出其可读能力时拆图或调用外部 renderer。内置 SVG 不是 Mermaid 引擎渲染结果；Mermaid 是保留的可编辑关系源，图形从同一结构化关系生成。

节点标签必须来自 PRD，连接不能指向不存在的节点。数据图每个点必须有事实 claim 与原文数值，不能把方案目标、预测或虚构例子画成实测。折线图必须提供递增的真实时间值；比例单位、样本和时间范围由模型检查并说明。

外部 renderer（包括未来接入 skill）把实际 PNG/SVG 和可编辑源保存进 run，提供哈希，用 `attach-diagram` 登记。不能仅提交“已经生成”的文字声明。渲染失败保留源文件及缺口，不偷偷换成装饰图，也不标记达标。

实际查看图片，检查：中文字体、正常缩放可读性、截断/重叠、箭头方向、分支条件、回路、数据轴/单位/比例、正文一致性。记录 `qa.readable`、`qa.consistent` 和具体观察证据。脚本不能代替视觉检查，也不会根据 SVG 文件存在就声称布局正确。

## 兼容输出

内置输出 SVG。目标空间支持 Mermaid 时可以使用源；支持图片时上传 SVG/PNG。不支持 SVG 的空间使用环境已有的转换/截图 skill 产生 PNG 并重新查看、登记。没有转换能力时交付可移植 SVG 包与清楚的待处理项，不能声称已适配该空间。

PRD 中可先使用 `![图标题](diagrams/图ID.svg)`，export 会转成包内 `assets/图ID.svg`。远端文档必须改成上传后的附件引用；源文件可以作为可编辑附件。
