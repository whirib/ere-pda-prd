# 精简中文 PRD 写法

本文为对三个上游 PRD 模板的重新编排与裁剪，保留问题、证据、范围、行为、验收和风险。按功能复杂度调整，条件不适用的章节可删除；写出完成文档，不把下面的指导语留给读者。

1. **一句话与背景**：谁遇到什么问题，采用什么方式取得什么结果，为什么此时做。
2. **用户与证据**：主要场景、当前流程、需求来源与重要假设；区分用户决定、事实和建议。
3. **目标与范围**：成功的可观察结果，本期包含、不包含及取舍理由。
4. **主流程**：入口、前置条件、行动、系统反馈、完成；重要分支和恢复就近说明。
5. **需求及验收**：按需求 ID 写行为与独立可验证结果。短功能可用表格，复杂行为用短段落。
6. **重要异常与权限**：适用的空状态、拒绝、并发、依赖失败和数据保存/恢复；勿重复已有条目。
7. **依赖、风险与未决项**：影响、具体验证/决策任务、已知责任角色；未知责任人明确待定。
8. **必要附录**：来源链接、决策记录、条件触发的模型评测/执行契约和图源。

流程图紧贴相关段落，标题说明它帮助理解的规则。正文仍要能脱离图独立说明关键行为。技术栈、数据库架构、商业模式、路线图和大量用户画像只在任务需要时加入。

示例风格：

> FR-02 保存失败后允许重试。用户点击“保存”时，系统保留当前输入并提示失败原因；重试成功后只产生一份需求记录。若用户离开页面，是否保留草稿仍待确认，因此本条目前不能交给研发按默认方案实现。

这段同时交代触发、结果、恢复及真实未决项，无需写成抽象“提升保存体验”。
